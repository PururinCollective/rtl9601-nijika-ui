      PON Downstream Usage

      This shows the downstream usage of the whole PON (all ONUs on this fibre), estimated from the idle frames of the OLT between two refreshes. The traffic of this SFP is shown under Forwarding.

      Note

      The value is the average over about 15 seconds; a shorter burst is shown at a fraction of its rate. Bar colour: blue below 50 %, yellow from 50 %, red from 80 %. No history is kept.

      Frame headers and management traffic are counted, so an idle PON reads slightly above zero. Dummy frames sent in place of idle frames are counted as load. The upstream is not measured.

      Forwarding

      In normal operation, the PON receive rate equals the host send rate.

      Note

      Traffic is forwarded in hardware, and these counters are the only measure. The PON counters run continuously; the host counters are cleared every 15 minutes, so only the rates are compared.

      Firmware Upgrade
      
        
      
          
          
        
      
        
      Upload stores the image in RAM only. Then write it to a partition above.
      
        
      
        
      
        
      
          Note: Try and Write
          
      Try boots a partition once, with the hardware watchdog armed. If the image does not come up, the SFP returns to the committed partition by itself. The next reboot after a successful Try also returns to the committed partition.
      
          
      Writing takes about 80 seconds and continues if this page is closed. Do not power off the SFP until it is done.
      
          
      /tmp is a RAM disk of 27 MB. The md5 of the kernel and the root file system is checked before anything is erased.
      
        
      
        
      
          Note: Software Version Reported to the OLT
          
      The OLT reads 0.0.0 for both software images unless the ONU identity switch is on; then it reads OMCI_SW_VER1 for image 0 and OMCI_SW_VER2 for image 1. The stock firmware may rewrite both keys when it boots.

          Note

          Safe Mode
          
      Safe mode is a recovery boot. For that boot the PON is off, the host port uses auto-negotiation, this page accepts admin / admin and root over SSH accepts the password admin. The saved password and SSH keys are not changed.
      
          
      To enter: power on the SFP, wait about 80 seconds, remove it, wait a few seconds. Repeat five times (three times if auto-negotiation is disabled), then leave it in. Each power-on must end 60 to 110 seconds after it starts.
      
          
      To leave: set a new password or add an SSH key if needed, acknowledge the banner, then reboot.
      
          
      Note: anyone who can power-cycle the SFP can enter safe mode.
